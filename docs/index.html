Supply Data Agents
La donnee validee devient de l'action

Cinq automatisations posees au-dessus d'un entrepot analytique dbt + DuckDB pour une enseigne de decoration et d'ameublement : alertes, self-service, rapports, garde de qualite et generation assistee, toujours avec un humain dans la boucle.

Donnees brutes → dbt (supply-dbt-warehouse) → 5 marts DuckDB testes → supply-data-agents : l'action
Le principe : un tableau de bord que personne ne regarde ne sert a rien. Chaque module ci-dessous part d'un probleme metier concret, se declenche tout seul (planification ou evenement), s'appuie uniquement sur les marts valides par les tests dbt, et produit une sortie directement utilisable : un message Slack, une reponse chiffree, un rapport, un diagnostic ou un brouillon a valider. Tout est teste (86 tests) et fonctionne sans cle d'API grace a des modes de repli deterministes.
🚨

Alerte rupture de stock

Alerte

Le probleme : une rupture sur un canape ou un luminaire best-seller coute des ventes chaque jour. L'information existe dans l'entrepot, mais personne ne la regarde a 7 h du matin.

Declencheur
Tous les jours a 7 h (cron ou n8n Schedule Trigger fourni).
Sortie
Message Slack pret a poster : produits en rupture, couverture, quantite de reapprovisionnement suggeree (30 jours de vente). Copie archivee en local.
7 h : planification→ Lecture du mart couverture de stock→ Selection des ruptures→ Calcul du reappro→ Slack #supply-alertes
Voir le module alerte_rupture Workflow n8n importable

Agent question-reponse metier

Self-service

Le probleme : "Quelle famille a la pire rotation ?" Chaque question simple devient un ticket pour l'equipe data. Le self-service existe rarement parce qu'on a peur de laisser un LLM ecrire du SQL sans filet.

Declencheur
A la demande : une question en francais, en ligne de commande ou branchee sur Slack.
Sortie
Une reponse chiffree en francais. Chaque echange est trace dans un journal d'audit (qui a demande quoi, quel SQL a tourne, quelle reponse est sortie).
Question en francais→ SQL (LLM ou bibliotheque de questions types)→ Garde : SELECT seul, 5 marts autorises→ Reponse chiffree + journal d'audit
Voir le module agent_qa

Rapport hebdomadaire supply et offre

Rapport

Le probleme : le comite du lundi matin a besoin des memes 5 indicateurs chaque semaine : taux de rupture, marges par famille, rotation, fiabilite fournisseurs (OTIF), stocks dormants. Les compiler a la main prend une heure et saute des qu'on est presse.

Declencheur
Chaque lundi matin (exemples cron, n8n et launchd fournis dans le module).
Sortie
Un markdown pret pour email ou Slack, et une page HTML autonome avec tuiles KPI, mini-graphiques et 3 points "ce qu'il faut retenir".
Lundi : planification→ 5 KPI calcules sur les marts→ Synthese (LLM ou regles)→ rapport.md + page HTML
Voir le module rapport_hebdo Exemple de rapport genere

Gardien de la qualite des donnees

Qualite

Le probleme : quand un test dbt casse, le message brut ("unique_supply_couverture_stock_id_produit failed") ne dit ni ce qui s'est passe, ni si c'est grave, ni quoi faire. Le diagnostic prend du temps d'expert.

Declencheur
Apres chaque run dbt : le module lit le run_results.json produit par dbt.
Sortie
Un diagnostic en francais par echec : categorie, gravite (bloquant ou avertissement), hypothese de cause, action proposee, lignes fautives en exemple. Code de sortie 1 si bloquant, pour arreter le pipeline.
Run dbt termine→ Lecture run_results.json→ Categorisation + gravite→ Diagnostic en francais→ Notification + arret si bloquant
Voir le module gardien_qualite

Fiches produits assistees

Generation + validation humaine

Le probleme : rediger des fiches produits (titre, description, points forts) pour des centaines de references prend des semaines. Mais une IA laissee seule invente des prix, des pourcentages et des superlatifs.

Declencheur
A la demande, par lot : les produits prioritaires issus du mart top/flop.
Sortie
Des brouillons de fiches dans une zone "a valider". Garde-fous automatiques (longueurs, pas de chiffre invente, pas de superlatif), puis approbation humaine explicite avant tout passage en "validee". Rien n'est publie sans ce geste.
Produits prioritaires→ Redaction (LLM ou gabarit)→ Garde-fous automatiques→ Zone a valider→ Approbation humaine
Voir le module fiches_produits
Ce que ce repo demontre cote produit : partir du probleme metier et non de la technologie, choisir le bon declencheur, mettre des garde-fous avant l'IA (lecture seule, allowlist SQL, validation humaine), prevoir un mode degrade sans LLM, et rendre chaque automatisation testable et observable. 86 tests automatises tournent a chaque modification, sans secret ni reseau.
